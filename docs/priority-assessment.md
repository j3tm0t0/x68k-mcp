## 回答検証

`scripts/check_priority_answers.py` の4問で、アドレス・同期範囲・未定義符号・GCR例外・未確定情報を確認する。保存済み回答は `--from-file` で追加API費用なしに再検査できる。実回答の語形（`bit8〜bit10`、`ありません`）も扱い、誤った0〜7や番地を拒否するテストを持つ。

- CRTC R20は$E80028、ビデオR0は$E82400。同期対象はR20 bit8〜10とR0 bit0〜2。
- R0 COLの2進10は図55では未定義、11は65536色。
- DMACチャンネル2のMTC/MAR/DARは$E8408A/$E8408C/$E84094。GCRは$E840FFに1個で、チャンネル0にはない。
- SIZ/COLの個別ビット番号は、今回の注釈では未確定とする。実回答が「R20の上位3ビット」と省略したため、bit8〜10は上位バイトの下位3ビットであり16ビット全体の上位3ビットではないことを注釈に追加した。

取り込み時の未確定事項を原本の記述として引用しないよう、table_provenance・照合状態・スコープは取り込み注釈であると回答指示にも明記した。

モデルはGPT-5.4 miniのまま。メーカー仕様全体の正しさや全質問の精度を保証する評価ではない。

## 残す課題と次の優先対象

1. 図54のSIZ/COL個別ビット番号は、図のセル配置や他の記述との整合性に疑問がある。独立した一次資料で確認するまで確定しない。既存のエミュレータ実装は同書に基づくため、独立検証とは扱わなかった。
2. CRTC R00〜R08の標準設定表（PDF235〜236）・算出式（PDF237図53）は別対象。設定値を求める質問が出た段階で評価する。
3. DMACの個別ビット定義・書き込み副作用は、今回の番地表からは確定しない。割り込み・エラー解除などの具体的な質問で、メーカー資料と照合する。
4. 部分的に構造化したページの未対象本文・図も、元OCRとして保持している。Webの回答根拠では現在そのページの構造化対象を優先するため、未対象部分の本文を併せて扱う方法は別途改善する。MCPの `get_page` では元OCRも取得できる。
5. 基板固有のMSM6258アナログ出力回路は、データシートの典型回路と分けて対象資料を特定する。

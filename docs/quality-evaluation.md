# MCPを使った回答の品質評価

利用者の質問を受けたLLMが、実際のMCPツールを自分で選び、取得した資料から回答する。その回答と取得履歴を、別の上位モデルが採点する。採点基準や正解値は回答役に渡さない。

## 通常テスト

```sh
uv sync --locked
make test
```

Pythonの単体・回帰・ローカルMCP結合テストを実行する。有料APIや本番MCPへは接続しない。クローンだけでテストでき、原本PDFや本番DBは不要。

fixturesには生成回答と既知の誤回答を含む。原本の抽出全文、ページ画像、APIキーは含めない。評価器は偽のモデルとMCPでも検証し、正解漏洩、未取得の根拠による合格、JSON形式、操作上限と間隔を確認する。

## 明示的な本番・有料評価

`OPENAI_API_KEY` を環境変数かGit対象外の `.env` に設定する。`.env` は値として読み、シェルとして実行しない。権限は600。キーをコマンド引数や公開ログに書かない。`.env.example` は設定名の例で、実キーを含めない。

```sh
# ケース一覧: ネットワークもモデルも使わない
uv run --no-sync python -m x68k_knowledge.mcp_evaluation --list-cases
# 有料の実評価: 1問、既定接続先は公開AWSネイティブMCP
make quality-live ARGS='--case screen-modes --answer-effort medium'
# 自分のMCPを検証する場合
make quality-live ARGS='--endpoint https://mcp.example.com/mcp --case crtc-sync --answer-effort medium'
```

回答役の既定モデルはGPT-5.4 mini、採点役はGPT-5.4。実行結果に実モデルIDと思考量を保存する。モデルは `--answer-model`・`--judge-model`、回答の思考量は `--answer-effort` で指定する。両役の同一モデルは許可しない。

Native版は標準Retrieveで出典付きの本文を実際に取得することも合格の必要条件。目次やページだけを読んで意味検索を検証したことにはしない。追加2問は `evals/holdout-rubrics.json`。

## 呼び出し制限

- 1問につきモデルが選ぶツールは最大6回、実行1回につき最大3問。
- MCP操作は10秒以上、質問開始は60秒以上の間隔。並列呼び出しはしない。
- 同じ出力ディレクトリでは実行間にも待機状態を引き継ぎ、同時実行をロックする。
- 自動リトライ・定期実行・通常テストへの有料呼び出し混入はしない。

SDK内部の初期化通信などもあるため、上記はHTTPパケット数の上限ではない。出力ディレクトリを変えて同時実行してよいという意味でもない。

## 判定と記録

正確さ・根拠・網羅性・実用性・満足度を0〜4点で採点する。全項目3点以上で、重大な誤り・未確認の主張・必須事項の欠落がなければ合格。モデルの高得点だけでは合格にせず、出典の実取得と既知の誤対応の固定検査も適用する。

固定検査は解像度とVRAM構成の誤対応、ソフト対応の誤記、疑似ツール呼び出し等を検出する。自由文のあらゆる誤りを検出できるものではない。Responsesのcommentaryとfinal_answerを分け、最終回答だけを解析する。

採点役は原本PDFを独立に読み直さない。基準のAI画像照合も人間の校正と区別し、理由・実回答・取得履歴を人が追えるようにする。基本19問と追加2問の改善・制約は [品質記録](aws-native-quality.md)。

結果はGit対象外の `tmp/mcp-evaluation/` に保存。JSONには取得本文も含むので、そのまま公開しない。APIエラーでも可視ドラフトと途中履歴を保持し、品質不合格と区別する。全問合格なら終了0、品質不合格・ケース実行中のエラーは1、実行前の設定エラーは2。

公開レポートは元の本文を除き、版・質問・取得箇所・判定理由と失敗履歴を記録する。選定ケースの合格を、未知の質問の正確さや統計的な正答率と扱わない。

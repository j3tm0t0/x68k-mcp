# 公開リポジトリの範囲

サービスへの接続と、自分で取り込み・デプロイ・検証するためのコードを公開する。稼働環境固有の運用状態や原本全文とは分ける。

| 対象 | 公開する内容 |
| --- | --- |
| `src/` | コーパス取り込み、ローカル検索、stdio MCP、評価器 |
| `aws/` | Managed KB、Gateway、読み取り専用Lambda、検算、CloudFrontの構築コード |
| `sources/` | 出典・版・対象範囲・章案内。原本そのものを含めない |
| `tables/` | 技術的事実の構造化注釈、出典とAI照合の来歴 |
| `tests/`・`evals/`・`scripts/` | オフラインテスト、評価基準、明示実行の検証ツール |
| `docs/` | 再現手順、設計、品質・コンテンツ公開の検討記録 |
| 設定例・ロックファイル | 実キーを含まない `.env.example`、依存の固定 |

`books/`・`data/`・`tmp/`・`.env`・個人設定・秘密鍵はGit対象外。ファイルをignoreしただけでは、既にGit履歴に入った情報は消えない。初回公開前にも公開候補の一覧と内容を確認する。

## 環境ごとの設定

AWSプロファイルは `AWS_PROFILE` または引数、CloudFrontのドメイン・Gatewayホスト・証明書ARNはCloudFormationパラメーター。個人環境の設定をコードの既定値にしない。サービス利用者向けの公開URLとGitHub上の公開Issueリンクは残す。

## 確認方法

公開候補だけを一時ディレクトリにコピーし、原本・DB・画像・APIキーがなくても `make test` 相当が動くことを確認する。stdio MCPの結合テストには合成した資料を使い、手元の本に依存しない。

環境ごとのデプロイ状態、監査の詳細、個人用の運用記録は公開リポジトリと分けて管理する。

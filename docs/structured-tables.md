# ページ画像から表を構造化する

通常の OCR では、結合セルが複数の解像度や色数に適用されることが失われる。回答モデルを大きくする前に、取り込み段階で行・列・結合セル・凡例・単位を明示する。

## 最初の対象

`tables/inside-x68000-p0171.json` は Inside X68000 PDF 171ページの表1を、原本ページ画像で照合して構造化したもの。

- 表示解像度・水平周波数・走査方式の注記・ハードウェア可否・ソフトウェア対応：8行。
- VRAM実画面・色数・ページ数・利用する表示解像度：4行。
- ソフトウェア対応とハードウェア設定可能性を分ける。
- 結合セルを対象の各行に展開する。実画面512×512は65,536色1ページ、256色2ページ、16色4ページで共通。
- 本文・ページ画像を公開するためのデータではなく、技術的な事実を質問に使える形式に整理している。

照合は Codex による原本画像の確認であり、人間による校正・査読ではない。`review_status=image_checked_by_ai_not_human_reviewed` と `review_method` を必須情報として保持する。非公式正誤表とは別の処理であり、正誤表の取り込みや本の記述の訂正は行っていない。

## 格納形式

JSON は `source_id`・元PDFの `source_sha256`・1始まりの `pdf_page`・図表ラベル・適用範囲・照合状態に加え、列定義と行のオブジェクトを持つ。整数、真偽値、null、文字列配列を保持するので、表示サイズ一覧や対応可否を失わずに検索・回答に利用できる。`unit` は検索用テキストへの変換にも使う。

元の `pages.jsonl`・`chunks.jsonl`・PDF は変更しない。取り込み後、コーパス内の `structured_tables/p0171.json` に再構築用の注釈を保存する。SQLite のページメタデータへ `structured_tables`・`structured_table_text`・`table_provenance` を追加し、表単位の検索チャンクを別途追加する。`start_char`・`end_char` は null で、OCR本文の範囲を装わない。

## 取り込み

```sh
.venv/bin/x68k-knowledge ingest-tables tables/inside-x68000-p0171.json \
  --corpus data/inside-x68000 \
  --db data/knowledge.sqlite3 \
  --sql-output tmp/structured-tables.sql
```

元資料のハッシュ、ページの存在、列とセルの整合性を検証する。再実行時は該当ページの構造化チャンクだけを置き換える。通常の `index` 再構築時もコーパス内の注釈を読み直す。

生成するSQL差分は、同じ版のSQLiteに注釈を反映するためのもの。先頭で資料ハッシュとページを検証し、異なる版なら更新前にエラーにする。AWSの検索用データは、注釈付きのページを再エクスポートして更新する。

## 検索と回答

ローカルのMCP全文検索は、キーワードが一致する構造化表を OCR チャンクより先に返す。MCP は表のセルと出典、照合状態を取得できる。

MCPの取得結果では、構造化表があるページの根拠にセルの関係を渡し、そのページの崩れた表OCRから関係を復元させない。ページ画像は配信しない。回答の引用先は元の資料・PDFページで、別の独立した一次資料として見せない。他のページのOCRは引き続き未校正。

## 今後の対象を増やす手順

1. 表のあるページを選び、ページ画像をレンダリングする。
2. 画像から列・行・結合セル・単位・凡例を JSON 化する。
3. 見出しだけでなく、全行と注記を画像に照合する。未確認セルは null 等で残す。
4. 取り込み・検索・質問による検証を行う。

Inside X68000 PDF33・171・237・238・264の5ページから7表、MC68000UM PDF118・120の2ページから3表、計7ページ・10表を追加した。第1バッチの選定理由と未確定事項は [必要性評価](priority-assessment.md) を参照。全PDFの自動画像処理や一括校正は未実装。画像読み取りの費用を抑えるためにも、表・レジスタ・ビットフィールドなど誤読の影響が大きい箇所から対象を増やす。


検証は `make test` のPythonテストと、明示的な実MCP評価で行う。表示モードだけでなく、VRAM・色数・ページ数の関係や未対応条件も検査する。[品質評価](quality-evaluation.md) を参照。


PDF264の音声図では、ADPCMパンポット周辺の小数点がOCRから落ちていたため、抵抗値と図中位置を構造化した。PPI側プルアップ部4.7kΩ、上段のADPCM出力側1.5kΩ、下段2.2kΩを原本画像で照合した。同じ図の別箇所の47kΩ・22kΩは実在するため一括置換しない。これは図中表記の注釈であり、X68000全機種の基板やLPF特性を検証したものではない。


MC68000UM PDF118のEA時間はサイズとアドレスモードを型付きで保持する。MULU.Wは32ビット結果でもソースはWordなので、(An)は4クロックを加算する。PDF120は表の70を固定時間と誤読した実回答を受け、38+2n、ソースWordのpopcount、最大70、Word EAの脚注を別表に整理した。具体値の計算例も検索できるが、原本に掲載された例と区別して導出と明記する。CPUの範囲はSection 8のMC68000等16ビットバスであり、同値でもMC68010の別表を根拠にしない。
